# Project specification

## Objective

Build an end-to-end, explainable hybrid product recommendation system for the NxtWise hiring assessment. It must demonstrate data inspection and preprocessing, product/user profiles, popularity baseline, item-based collaborative filtering, TF-IDF content filtering, hybrid ranking, Top-N results, seen-item filtering, cold start, Flask REST API, React UI, evaluation, tests, and documentation.

## Dataset

The sole selected dataset is **H&M Personalized Fashion Recommendations**. Retailrocket is abandoned and must not be used. Actual files, schema, data quality, working-subset strategy, image availability, and product metadata must be verified in Phase 1.

## Constraints

- Do not invent product metadata, images, customers, interactions, metrics, or recommendation explanations.
- Do not load the full transaction file blindly. Choose a reproducible working subset only after inspection and document the evidence.
- Keep offline preprocessing/training separate from online serving. Do not train in API requests.
- MySQL is application persistence, not an ML matrix store.
- Use real, verified H&M metadata for product presentation and content features.
- Every numeric result must be generated by executed code.

## Current boundary

This is Phase 0 only. The repository contains no H&M data, preprocessing code, models, database schema, API, or frontend feature.
